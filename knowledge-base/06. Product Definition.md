# 06. Product Definition

> **Status:** Living document
> **Version:** 1.0
> **Last Updated:** 2026-09-27

---

## 1. Product statement

> **BOUND is an offline document distribution service plus forensic verifier. It encrypts a
> document once for many recipients, embeds a unique invisible session fingerprint each time
> a recipient decrypts it, and records every decryption as a post-quantum-signed event in a
> quorum-replicated ledger so any leaked copy can be attributed to a recipient and session.**

---

## 2. Core objects (the data model in one page)

```text
Document
 ├── document_id       DOC-001
 ├── original_filename report.pdf
 ├── document_hash     SHA-256 of plaintext
 ├── aes_nonce         12 bytes
 ├── ciphertext        AES-256-GCM(plaintext)
 ├── authorized_recipients [ALICE, BOB]
 └── wrapped_keys
      ├── ALICE: {kem_ciphertext, wrapped_key_nonce, wrapped_key, mlkem_variant}
      └── BOB:   {…}

Recipient
 ├── recipient_id      ALICE
 ├── mlkem_pk/sk       ML-KEM-768
 ├── mldsa_pk/sk       ML-DSA-65
 └── key_storage       "encrypted" | "legacy"

Decryption Event (canonical, signed)
 ├── event_type        DOCUMENT_DECRYPTED
 ├── document_id, document_hash
 ├── recipient_id, session_id, watermark_id, nonce
 └── timestamp

Watermark ID
 └── WM-<26 base32 chars>   (128-bit opaque)

Ledger Entry (per node)
 ├── seq, previous_hash, current_hash
 ├── event, signature (recipient), public_key_b64
 ├── node_id, node_signature
 └── timestamp

Checkpoint (per node, per append)
 └── checkpoint_index, entry_count, merkle_root, timestamp, node_id, node_signature
```

## 3. The user-visible product

### Files page (owner)
- Upload any file type + extension, select recipients, share.
- Table with format badge, search, filter, sort, pagination.
- Detail drawer: metadata + every recorded decryption session.

### Shared with me (recipient)
- Documents where you are an authorized recipient.
- Unlock dialog if keys are locked; decrypt button; download the marked copy.
- Output keeps the original format when possible; unknown types become `.zip`.

### People
- Directory with key-storage type, PQC variants, key fingerprints, document counts.

### Verify (investigator)
- Upload a leaked artifact of any supported type.
- Shows detected `format`, watermark ID, recipient, session, timestamp, signature validity,
  ledger quorum, and whether the full chain is strictly valid.
- Links to the document and the matching audit entry.

### Audit
- Ledger entries with per-entry quorum + valid nodes.
- Merkle root, per-node checkpoints, divergent nodes.
- "Re-sync from quorum" repair button.

### Security demos (secondary)
- 6 runnable demonstrations, including all-node consistent admin tampering.
- Demo results refresh the Audit view.

## 4. Guarantees the product does make

| # | Guarantee | Evidence |
|---|---|---|
| G1 | Each decryption gets a distinct 128-bit fingerprint | tests, `dct_watermark.generate_watermark_id` |
| G2 | The event is signed by the recipient's ML-DSA key | `forensic/events.py` |
| G3 | Each ledger node independently signs entries + checkpoints | `ledger/ledger.py` |
| G4 | An edit to any ledger file is detected | `verify_ledger_node()` |
| G5 | Attribution survives 1 corrupt node (local 3/4) | `test_ledger_v2.py` |
| G6 | The whole system runs offline | no external calls |
| G7 | Supported formats keep working after watermarking | format tests |
| G8 | The verifier never crashes on garbage input | `test_extract_never_raises_on_garbage` |

## 5. Guarantees the product does NOT make

| # | Non-guarantee | Where stated |
|---|---|---|
| N1 | Watermark survives every transformation | README limitations, `18` |
| N2 | Watermark survives a camera/screenshot | PS §19, `18` |
| N3 | A signature proves a human acted | PS §6, README |
| N4 | Full non-repudiation (signing is server-side after unlock) | README, `17` |
| N5 | Absolute immutability | README ("tamper-evident") |
| N6 | BFT consensus under a compromised majority | README, `25` |
| N7 | ZIP fallback protects the inner file if extracted | README, `12` |
| N8 | Endpoint security / tamper-proof viewer | PS §10, `18` |

## 6. Modes of operation

| Mode | Env | Ledger | Quorum |
|---|---|---|---|
| **local** (default) | `BOUND_LEDGER_MODE=local` | 4 directories, one process | 3 / 4 |
| **lan** | `BOUND_LEDGER_MODE=lan` | one node agent per device | strict majority of joined members |

Other knobs:
- `BOUND_LEDGER_ROOT` — per-device data dir for LAN nodes.
- `BOUND_NODE_ID`, `BOUND_NODE_PORT`, `BOUND_COORDINATOR_URL`, `BOUND_ENROLL_TOKEN`
- `BOUND_MEMBERS_FILE`, `BOUND_LAN_TIMEOUT`, `BOUND_HEARTBEAT_SECONDS`, `BOUND_ANNOUNCE_TIMEOUT`

---

## 7. Product boundaries

- **In scope:** attribution after a leak, offline operation, format preservation, tamper
  evidence, recipient/session identification.
- **Out of scope:** preventing leaks, endpoint DRM, camera resistance, legal non-repudiation,
  production scale, formal audit, hardware key storage.
