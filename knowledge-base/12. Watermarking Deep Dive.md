## 1. Watermark ID derivation

```python
material = f"{document_hash}|{recipient_id.upper()}|{session_id}|{nonce}".encode()
digest   = sha256(material).digest()[:16]          # 128 bits
watermark_id = "WM-" + base64.b32encode(digest).decode().rstrip("=")
```

- Format: `WM-` + 26 RFC4648 base32 chars (`A-Z2-7`).
- Regex: `^WM-[A-Z2-7]{26}$`.
- Entropy: **128 bits** (v1 was `WM-` + 12 hex = 48 bits).
- Deterministic for the same inputs; unique across recipients/sessions/nonces.
- Contains **no identity** — only the ledger can map it.

Session/nonce sources (`forensic/events.py:75`):
- `session_id = "SES-" + uuid4().hex[:6].upper()` (24 bits → collisions possible, but paired
  with a 128-bit nonce and the document hash).
- `nonce = os.urandom(16).hex().upper()` (128 bits).

✅ Tests: `test_watermark_v2.py::test_watermark_id_format_and_determinism`,
`test_watermark_id_uniqueness_across_recipients_and_sessions`.

## 2. Payload framing (all DCT channels)

```text
id (29 ASCII bytes) ‖ CRC32(id) (4 bytes, big-endian)   = 33 bytes = 264 bits
repeat each bit R=5 times                                = 1,320 slots
```

- Decoder accumulates votes per bit across every 8×8 block, majority-votes within each
  repetition group, then decodes bytes and **verifies CRC32 before accepting**.
- Any failing candidate is rejected and extraction continues.

Constants (`dct_watermark.py`):

| Constant | Value |
|---|---|
| `PAYLOAD_BYTES` | 33 |
| `WATERMARK_BITS` | 264 |
| `REPETITION` | 5 |
| `EXTENDED_BITS` | 1320 |
| `Q` (QIM step) | 16 |
| `COEFF_POS` | (3, 2) |
| `DPI` (rasterize / PSNR) | 150 |
| `JPEG_QUALITY` | 85 |
| `MIN_IMAGE_SIDE` | 64 px |
| `MIN_IMAGE_BLOCKS` | `EXTENDED_BITS * 2` = 2,640 8×8 blocks |

## 3. DCT QIM maths

1. Convert RGB → YCbCr, keep chroma untouched.
2. Split Y into 8×8 blocks (zero-padded to multiples of 8).
3. 2-D DCT-II (`scipy.fftpack.dct`, orthonormal).
4. Pick one mid-frequency coefficient `(3,2)` per block (robustness vs. invisibility).
5. Quantization Index Modulation parity:
   - `quant = round(coeff / Q)`
   - if `(quant & 1) != wanted_bit`, nudge `quant` by ±1 (direction keeps the coefficient
     closest to its original value).
   - `target = quant * Q`.
6. Write the coefficient back via the orthonormal basis block, clipping to `[0,255]` in
   pixel space.
7. Because clipping can pull the realised coefficient off target, a small refinement loop
   (up to 3 iterations) re-applies the correction and re-measures the actual coefficient.

Embedding is **cyclic**: bits are tiled across as many blocks as the image/page has, so a
large image holds many redundant copies.

Extraction is **blind** (no original needed): read coefficient parity per block, accumulate
votes by bit position, majority-decode, CRC-check.

✅ Tests: exact round-trip on PDF both modes, image round-trip per format, JPEG re-render
fallback, PSNR thresholds.

## 4. PDF channels

### 4.1 `preserve` mode (default)
- Insert the ID as **invisible text** at four corners of every page (`render_mode=3`,
  helv 6pt). Text chunks of 8 chars if the ID is wider than the page.
- For every embedded raster image with ≥ MIN_IMAGE_SIDE and ≥ MIN_IMAGE_BLOCKS:
  DCT-QIM the Y channel, re-save as **PNG when the source was PNG/alpha**, else **JPEG q85**,
  preserving an alpha channel when present.
- Returns the edited document. Vector text stays selectable and searchable.
- Measured: 3-page sample 2,969 B → 2,632 B. Text-only pages are effectively byte-identical.

### 4.2 `rasterize` mode (optional)
- Render each page at 150 DPI, DCT-QIM the whole page, insert the invisible text too, and
  rebuild the PDF with one JPEG per page.
- Robust to full flattening/re-rendering, but loses text selection.

### 4.3 Extraction order for PDF
1. scan `page.get_text()` for `WM-[A-Z2-7]{26}` → exact recovery via text channel.
2. decode each unique embedded image stream via DCT.
3. render each page at 150 DPI and accumulate DCT votes.
4. CRC/regex validation at every step.

## 5. Per-format matrix

| Kind | Extensions | Channel | Output | Fallback trigger |
|---|---|---|---|---|
| **PDF** | `.pdf` | Invisible text + per-image DCT QIM | Same PDF, text preserved | unreadable PDF |
| **Image** | `.png .jpg .jpeg .bmp .webp .tif .tiff` | Y-channel DCT QIM | Same format: PNG/BMP/TIFF-LZW/WebP lossless, JPEG q90; alpha preserved | animated, palette, too small, re-encode failure |
| **Text** | `.txt .md .markdown .log .csv .tsv .json .xml .yaml .yml .html .htm .ini .cfg` | Zero-width marker | UTF-8 with marker; visible content unchanged | invalid UTF-8, no safe insertion point |
| **OOXML** | `.docx .xlsx .pptx` | Zero-width marker in one XML member | ZIP rebuilt, all other members byte-for-byte | no safe member |
| **Container** | everything else | ZIP archive comment `BOUNDWM1:<WM-ID>` | original bytes inside a `.zip` (or comment on an existing ZIP) | always available |

### Text insertion points (by extension)
- `.json` → inside the first complete string literal.
- `.csv`/`.tsv` → end of the first line (before CR/LF).
- `.yaml`/`.yml` → appended comment line.
- `.xml`/`.html`/`.htm` → comment before the last `</…>`.
- everything else → appended at the end of the file.

### OOXML member selection
- `.docx` → `word/document.xml` (first `w:t`, else a run before `</w:body>`).
- `.xlsx` → `xl/sharedStrings.xml`, else first worksheet, else `docProps/core.xml`
  (adds a `dc:description` with namespace repair).
- `.pptx` → `ppt/slides/slide1.xml` (first `a:t`).

### Zero-width encoding
```text
U+2060 guard ‖ bit 0 = U+200B, bit 1 = U+200C (264 bits) ‖ U+2060 guard
```

## 7. Robustness matrix (what survives)

| Transformation | Text channel | DCT channel | Container |
|---|---|---|---|
| Copy / re-save PDF | ✅ | ✅ | ✅ |
| JPEG re-encode embedded image | n/a | ✅ (≤ some q) | n/a |
| Full-page flatten → JPEG | ❌ text lost | ✅ rasterize, and preserve if page was rendered (tested) | n/a |
| Light crop/rescale | ❌/partial | partial | n/a |
| Screenshot / camera | ❌ | not guaranteed | n/a |
| Print + scan | ❌ | not guaranteed | n/a |
| Extract inner file from ZIP | n/a | n/a | ❌ wrapper only |

> The honest statement: **"forensically robust against selected common transformations, not
> universally unremovable."** This is exactly the PS's required framing.

## 8. Container fallback trade-off

- The watermark lives in the ZIP **archive comment**.
- If an attacker extracts the inner file and shares only that, the container watermark does
  not travel with it.
- Only the wrapper is protected. ✅ Documented in README and tests.

---

## 9. Why DCT was chosen over DWT/SVD

- 🟣 **DECISION:** DCT is simple, fast, deterministic, has no external ML dependency, and
  survives JPEG re-encoding — the dominant lossy transform for real documents.
- DWT would need wavelet choices and multi-level tuning; SVD is fragile under cropping and
  much slower. Neither was necessary to meet the PS's "robust against selected
  transformations" bar.
