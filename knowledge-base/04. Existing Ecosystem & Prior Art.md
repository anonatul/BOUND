## 1. The five adjacent technology families

BOUND sits at the intersection of five mature fields. It is honest that **none of the
primitives are new**; the composition and the offline operation are the contribution.

| Family | Representative tools / concepts | What it gives | Why it is not enough alone |
|---|---|---|---|
| **Access logging / SIEM** | audit logs, syslog, SIEM, cloud audit trails | who accessed what | mutable by privileged insiders; not bound to the artifact |
| **Digital watermarking** | Digimarc, IMATAG, NexGuard, DCT/DWT/SVD research | per-copy IDs | needs a trusted registry; no cryptographic proof |
| **DRM / IRM** | Microsoft Purview IRM, Adobe, Fasoo | prevents copying | defeated by camera/scan; breaks workflows |
| **Blockchain / DLT** | Hyperledger Fabric, CometBFT, Ethereum | tamper-evident records | needs network; public privacy issues; overkill |
| **Post-quantum crypto** | liboqs, PQClean, `pqcrypto`, OQS-OpenSSL | quantum-resistant KEX/signatures | just primitives; no attribution workflow |

## 2. Document watermarking prior art

### 2.1 Frequency-domain watermarking
- Classic technique: render/transform image content, embed bits in DCT/DWT/SVD coefficients.
- BOUND uses **DCT QIM** on the luminance (Y) channel, coefficient `(3,2)`, step `Q=16`,
  with repetition-5 and CRC32. This is textbook robust-invisible watermarking.

### 2.2 Text / document watermarking
- Text watermarks often use whitespace, line-shift, or zero-width character encoding.
- BOUND uses **zero-width Unicode** (U+200B / U+200C framed by U+2060) for text and OOXML,
  plus an **invisible PDF text layer** (render mode 3) for exact PDF recovery.

### 2.3 Collusion / per-recipient fingerprinting
- Per-recipient fingerprints are the standard anti-collusion approach.
- BOUND differentiates by deriving the fingerprint from **document + recipient + session +
  nonce**, making it per-session and unlinkable without the ledger.

- 🟣 **DECISION:** BOUND deliberately chose **simpler, offline, format-native** channels
  over heavy ML-based robust watermarking, because the PS prioritizes verifiability and
  offline operation over camera resistance.

## 3. Blockchain / DLT options the PS named

The PS explicitly says to evaluate:

| Option | Pros | Cons for this PS | BOUND verdict |
|---|---|---|---|
| **Hyperledger Fabric** | real permissioned DLT, rich tooling | heavy, needs Docker network + MSP setup; hard to run on one air-gapped laptop; harder to demo | 🟣 not chosen |
| **CometBFT / Tendermint** | BFT consensus, mature | operational complexity, need ≥4 validators, networking | 🟣 not chosen |
| **QBFT (GoQuorum/Besu)** | enterprise BFT | Ethereum toolchain weight, no need for EVM | 🟣 not chosen |
| **Custom append-only signed ledger** | trivial offline deploy, per-node PQC signatures, Merkle checkpoints, quorum, LAN | not a formal BFT protocol; no consensus rounds | ✅ **chosen** |

- ✅ **VALIDATED:** the custom ledger gives the required property (an admin without node
  keys cannot forge a consistent rewrite) and runs with zero extra infrastructure.
- 🔴 **REJECTED claim:** do not call it "blockchain consensus" or "Byzantine fault
  tolerant". It is **tamper-evident and quorum-replicated**.

## 4. Post-quantum ecosystem

| Library | Role | BOUND usage |
|---|---|---|
| **liboqs / PQClean** | reference C implementations of NIST PQC | underneath `pqcrypto` |
| **`pqcrypto` (PyPI)** | Python bindings to liboqs/PQClean | direct dependency for ML-KEM/ML-DSA |
| **OQS-OpenSSL / oqs-provider** | PQC in TLS | not used |
| **BoringSSL / AWS-LC PQC** | PQC in TLS stacks | not used |
| **`cryptography`** | AES-256-GCM, scrypt, HMAC | direct dependency |

- 🟣 **DECISION:** never implement ML-KEM/ML-DSA ourselves — the PS mandates established
  libraries. `pqcrypto_wrapper.py` fails loudly rather than falling back.

## 5. Comparable "attribution after leak" approaches

| Approach | Mechanism | Weakness BOUND targets |
|---|---|---|
| DLP + audit | inspect/block egress, log events | no artifact-bound proof |
| Visible deterrent watermark | name/ID on every page | croppable, same for a group, visually intrusive |
| Per-user watermark + DB | unique ID, relational DB | DB is a single forgeable authority |
| Document rights management | encrypt + policy | camera/scan bypass |
| Public timestamping | hash on public chain | needs internet, privacy |

BOUND's niche: **artifact-bound, cryptographically signed, offline, quorum-replicated.**
