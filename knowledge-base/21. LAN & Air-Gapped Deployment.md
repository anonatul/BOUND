# 21. LAN / Air-Gapped Deployment

> **Status:** Living document
> **Version:** 1.0
> **Last Updated:** 2026-09-27
> **This is the configuration that actually satisfies "no single administrator can alter the record".**

---

## 1. Topology

```text
        ISOLATED WIFI ROUTER (no Ethernet / WAN uplink)
   Coordinator (app + frontend) ◄── auto-join ── laptop B
           │                                  laptop C
           └── HTTP ── every member device runs one node agent
```

Each witness device:
- generates its own ML-DSA-65 keypair on first start,
- keeps the private key on that device (chmod `0600`),
- owns its own `ledger.jsonl` + `checkpoints.jsonl`,
- announces itself to the coordinator and heartbeats every 30 s.

---

## 2. Quorum rule: majority of members

| Members | Quorum |
|---|---|
| 1 | 1 |
| 2 | 2 |
| 3 | 2 |
| 4 | 3 |
| 5 | 3 |
| 6 | 4 |

The threshold is derived from **membership**, not from how many nodes happen to be online.
A coordinator that knocks nodes offline cannot lower the bar.

> With 2 devices the split is 1 node each and quorum 2: **both must be online** and neither
> alone can forge. Add laptops and the quorum scales automatically.

---

## 3. Network setup

1. Router with **no Ethernet/WAN cable**.
2. Disable client/AP isolation so devices can talk to each other.
3. Give each device a static IP (example: coordinator `192.168.50.10`). No DNS needed.
4. Plain HTTP is intentional: the isolated router is the security boundary.
   (Production hardening: terminate TLS locally with a self-signed CA.)

## 4. Start the coordinator

```bash
export BOUND_LEDGER_MODE=lan
export BOUND_ENROLL_TOKEN="pick-a-shared-secret"   # optional gate
uv run uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
```

---

## 5. Start one node per witness device

Linux/macOS (from the repo):
```bash
BOUND_NODE_ID=laptopB \
BOUND_NODE_PORT=9101 \
BOUND_COORDINATOR_URL=http://192.168.50.10:8000 \
BOUND_ENROLL_TOKEN="pick-a-shared-secret" \
./scripts/start_node.sh
```

Windows PowerShell (each command on its own line; do not join them):
```powershell
cd $HOME\Documents\BOUND
.\scripts\start_node.ps1 -NodeId laptopB -Port 9101 -CoordinatorUrl http://192.168.50.10:8000
```

If the script misbehaves, run the node directly (same thing):
```powershell
$env:BOUND_NODE_ID = "laptopB"
$env:BOUND_NODE_PORT = "9101"
$env:BOUND_COORDINATOR_URL = "http://192.168.50.10:8000"
uv run uvicorn backend.app.ledger.node_agent:app --host 0.0.0.0 --port 9101
```

## 6. Verify membership

```bash
curl http://<device-ip>:9101/node/info          # public key + chain head (never the private key)
curl http://192.168.50.10:8000/api/ledger/members
```

The Audit view shows live members, required quorum, and any divergent node.

---

## 7. Membership & node API

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/ledger/register` | node announces itself; URL derived from observed source IP; key pinned |
| GET | `/api/ledger/members` | registered members + current quorum |
| DELETE | `/api/ledger/members/{id}` | remove a member |
| GET | `/health`, `/node/info` | liveness; public key + chain head |
| GET | `/node/entries` | full chain (peer sync) |
| GET | `/node/find?watermark_id=` | entry + chain-prefix validity |
| POST | `/node/append` | coordinator proposes; node validates then signs |
| POST | `/node/verify` | node self-verifies chain + checkpoints |
| POST | `/node/sync` | adopt a peer chain, re-signing locally |

A newly joined node is seeded with the existing chain automatically.

---

## 8. Failure behaviour

| Situation | Behaviour |
|---|---|
| One node down (of 4+) | majority quorum still commits and attributes |
| A node edited on its device | `verify_all_ledgers` flags it; repair re-syncs peer-to-peer, re-signing locally |
| Fewer than quorum reachable | commits refuse (explicit error) |
| Node re-announces with a different key | rejected (public key pinned on first join) |
| Coordinator restarts | members persist in `ledger-members.json`; nodes re-heartbeat |

---

## 9. Why this defeats the privileged coordinator

- The coordinator never sees node private keys.
- `/node/append` makes each node **independently recompute** `current_hash` and chain
  continuity before signing; a malicious coordinator cannot smuggle a bad entry.
- Rewriting the whole history would require the private keys of a majority of devices —
  i.e. physically compromising each device.

- ✅ Evidence: `backend/tests/test_ledger_lan.py` runs **four real node-agent processes on
  localhost** and proves commit, quorum, divergence detection and peer repair.

---

## 10. Demo recipe for the "no single admin" beat

1. Start coordinator + 3 witness laptops.
2. Decrypt once → audit shows 3/3 (or 4/4) node signatures.
3. On one witness, edit `ledger.jsonl` → Audit flags that node; attribution still works.
4. Click **Re-sync from quorum** → the node is restored by re-signing, not by file copy.
5. Show `node_mldsa_sk.b64` is only on that device and only its public key is ever returned.
