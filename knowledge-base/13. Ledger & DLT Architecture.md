## 1. Design summary

BOUND's audit layer is a **replicated append-only signed chain**, not a consensus blockchain.

```text
        Decryption event (signed by recipient)
                    │
                    ▼
      current_hash = SHA256(canon_event ‖ recipient_sig ‖ previous_hash)
                    │
        ┌───────────┼───────────┬───────────┐
        ▼           ▼           ▼           ▼
     node1        node2       node3       node4      (local mode)
   own ML-DSA   own ML-DSA  own ML-DSA  own ML-DSA
   entry sig    entry sig   entry sig   entry sig
   checkpoint   checkpoint  checkpoint  checkpoint
        └───────────┴───── quorum ────┴──────────┘
                 3 of 4 required
```

In LAN mode the four columns are **four real devices**, each with a node agent.

- 🟣 **DECISION:** custom ledger over Hyperledger Fabric/CometBFT (see `04`, `26`).

## 2. Entry schema

```json
{
  "seq": 0,
  "event": { "...canonical decryption event..." },
  "signature": "<recipient ML-DSA signature b64>",
  "public_key_b64": "<recipient ML-DSA public key b64>",
  "previous_hash": "<64 hex, genesis = 000…0>",
  "current_hash": "<64 hex>",
  "timestamp": "2026-09-14T10:30:00Z",
  "node_id": "node1",
  "node_signature": "<node ML-DSA signature b64>",
  "document_id": "DOC-001",
  "recipient_id": "ALICE",
  "session_id": "SES-9F82A1",
  "watermark_id": "WM-…",
  "document_hash": "<sha256 hex>"
}
```

`current_hash = SHA256(canonical_event_bytes ‖ recipient_signature_b64 ‖ previous_hash)`.

`node_signature` covers exactly these 9 fields
(`_entry_signature_payload`):
`seq, previous_hash, current_hash, signature, document_id, recipient_id, session_id,
watermark_id, timestamp`.

> Note: `node_id` and `node_signature` are not inside their own signed payload; the verifier
> knows which node file it is reading and uses that node's public key, so a node signature
> cannot be replayed on another node's file.

## 3. Checkpoints

Every append also writes a checkpoint to `nodeN/checkpoints.jsonl`:

```json
{
  "checkpoint_index": 0,
  "entry_count": 1,
  "merkle_root": "<root over entries[0..entry_count-1].current_hash>",
  "timestamp": "…",
  "node_id": "node1",
  "node_signature": "<over the 5 fields above>"
}
```

Merkle construction (`_merkle_root`): SHA-256 internal nodes, duplicate the last node on an
odd level. Genesis/empty root = `"0"*64`.

Checkpoint validation catches **silent truncation or rewrite** even when the hash chain
happens to look internally consistent.

- ✅ Tests: `test_checkpoint_tamper_detected`, count mismatch checks in `verify_ledger_node`.

---

## 4. Per-node identity

- Each node has `node_mldsa_pk.b64` / `node_mldsa_sk.b64` under `ledger/<node>/` (local) or
  `BOUND_LEDGER_ROOT/<node_id>/` (LAN).
- Keys are generated on first use and never overwritten.
- In LAN mode the agent `chmod 0600` the private key and only ever exposes the public key
  via `/node/info`.
- Node variant is ML-DSA-65.

## 5. Local mode verification

`verify_ledger_node(node_id)` checks, in order:
1. JSONL parses strictly (malformed lines are **errors**, not skipped).
2. `seq` equals the index (no gaps/reordering).
3. `previous_hash` links to the previous entry (genesis for entry 0).
4. recomputed `current_hash` matches.
5. `node_signature` verifies against this node's public key.
6. checkpoint count equals entry count.
7. every checkpoint index/entry_count/merkle_root/node_id/node_signature verifies.

`verify_all_ledgers()`:
- strictly valid only if **all nodes valid** and all chains identical in length and last hash;
- also returns `quorum` (= count of valid nodes), `quorum_ok` (≥3), `merkle_root` from the
  majority chain, `majority_last_hash`, and `divergent_nodes`.

`verify_entry_quorum(watermark_id)`:
- groups the same watermark's entry by `current_hash` across nodes,
- keeps only nodes whose chain prefix up to that entry fully verifies,
- succeeds if any single `current_hash` group has **≥3 valid nodes**,
- returns valid nodes + a representative entry.

- ✅ Tests: `test_ledger_v2.py` (7 tests), including single-node tamper survival and
  consistent all-node rewrite rejection.

## 6. Commit rules (local)

1. `previous_hash` = **majority** last hash across nodes (so a single divergent node cannot
   set the head).
2. A node participates only if `verify_ledger_node()` passes, `seq` is continuous and its
   last hash == `previous_hash`.
3. Entry and checkpoint are appended with `flush + fsync`.
4. `successes >= 3` required, else `RuntimeError`.

`repair_divergent_nodes()`:
- requires ≥3 valid nodes with an **identical** chain signature `(length, last_hash)` to
  establish a canonical history;
- rewrites each bad node **by re-signing every entry with that node's own key** and rebuilding
  its checkpoints (never a blind file copy);
- refuses when quorum is not available.

## 7. LAN mode

### 7.1 Node agent API (`node_agent.py`)

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | liveness |
| GET | `/node/info` | node_id, **public** key, entry count, last hash |
| GET | `/node/entries` | full chain (used for peer seeding) |
| GET | `/node/find?watermark_id=` | entry + chain-prefix validity |
| POST | `/node/append` | coordinator proposal; node independently validates then signs |
| POST | `/node/verify` | node self-verifies chain + checkpoints |
| POST | `/node/sync` | adopt a peer chain, re-signing locally |

`/node/append` independently recomputes
`SHA256(canonical_event ‖ signature ‖ previous_hash)` and rejects mismatches with HTTP 400/409.
A compromised coordinator cannot make a node sign an entry that does not chain to its head.

`/node/sync` re-validates the whole incoming chain first and **refuses to sync to an empty
chain**, then re-signs every entry locally.

### 7.2 Dynamic membership (`members.py`)

- A device starts the agent → it announces itself to `POST /api/ledger/register`.
- The coordinator derives the URL from the **observed source IP** + advertised port, so a
  node cannot claim someone else's address.
- The public key is **pinned on first join**; re-announcing with a different key is rejected.
- Membership is only changed by explicit join/remove; an offline node is reported
  unreachable, not dropped.
- Quorum rule: **strict majority of registered members** = `n // 2 + 1`:

| Members | Quorum |
|---|---|
| 1 | 1 |
| 2 | 2 |
| 3 | 2 |
| 4 | 3 |
| 5 | 3 |
| 6 | 4 |

Because the bar is set by **membership**, a coordinator that knocks nodes offline cannot
lower the threshold.

### 7.3 LAN verification/commit

`lan.commit_event()` requires at least `quorum` reachable nodes, takes the majority head,
proposes to everyone, and requires `quorum` accepts. `lan.verify_entry_quorum()` asks every
node `/node/find`, keeps only nodes whose `valid_prefix` is true, and requires a `>=
quorum` group on the same `current_hash`.

- ✅ Tests: `test_ledger_lan.py` spins **4 real uvicorn processes on localhost** and proves
  commit, verification, one-node-missing quorum, divergence detection and peer repair.

## 8. What an attacker with file access can and cannot do

| Attacker capability | Local mode | LAN mode |
|---|---|---|
| Edit one node's file | ❌ detected immediately | ❌ detected |
| Delete/truncate one node | ❌ detected (checkpoints) | ❌ detected |
| Rewrite **all** files and recompute all hashes | ❌ node signatures fail (no node keys) | ❌ impossible unless every device is compromised |
| Change the event and re-sign | ❌ needs recipient ML-DSA key | ❌ same |
| Forge a watermark not in the ledger | ❌ `NO_LEDGER_MATCH` | ❌ same |
| Compromise a majority of node keys | ✅ possible (out of model) | ✅ possible (out of model) |

> Honest framing: **"The ledger makes unauthorized modification detectable and prevents a
> single administrator or compromised node from silently rewriting the agreed history,
> assuming the trust/fault model holds."** Never say "immutable".

## 9. Why not a "real" BFT blockchain

- The requirement is tamper-evidence + no-single-admin, not multi-party consensus with
  unknown participants.
- A BFT network adds operational weight with no benefit for a closed, air-gapped deployment.
- Node signatures + quorum already give the required detection guarantee.
- The PS explicitly allows the "simpler custom append-only ledger for the prototype" as a
  fallback. BOUND chose that and made it strong.
