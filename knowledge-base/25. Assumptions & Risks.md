## 1. Assumptions

| # | Assumption | Basis | If wrong | Label |
|---|---|---|---|---|
| A1 | The isolated LAN is physically secure | air-gapped router, no uplink | plain HTTP can be sniffed; node URLs spoofed on-LAN | 🟡 |
| A2 | A quorum of node keys stays honest | separate devices, chmod 0600 | majority compromise forges history | 🟡 |
| A3 | The recipient endpoint is not fully trusted | stated threat model | endpoint attacker can bypass watermark | 🟡 |
| A4 | `pqcrypto`/liboqs implementations are correct | NIST standards + widely used | PQC breaks | 🟡 |
| A5 | Document leaks retain *some* watermark channel | empirical robustness tests | attribution fails → `NO_WATERMARK` | 🟡 |
| A6 | Verifier uses the ledger from a quorum, not one node | `verify_entry_quorum` | single-node coercion could mislead | ✅ mitigated |
| A7 | AES-GCM nonces are never reused | 12 random bytes per encryption | confidentiality break | ✅ by construction |
| A8 | Clock skew is small | same LAN, demo | timestamp ordering off | 🟡 |
| A9 | Users keep passphrases safe | auth model | key compromise | 🟡 |
| A10 | The judge values honesty over hype | PS explicitly demands it | n/a | 🟢 |

## 3. Risk posture statement

> BOUND's biggest risks are **endpoint trust** and **watermark survivability** — both are
> properties of the problem, not bugs. The prototype's answer is to *state them* and to make
> the failure direction safe: a destroyed watermark yields `NO_WATERMARK`, never a wrong
> attribution.
