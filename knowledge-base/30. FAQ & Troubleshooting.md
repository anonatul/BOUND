## A. Concept FAQ

**Q: Does BOUND prevent leaks?**
A: No. It provides **attribution after** a leak. Prevention is explicitly out of scope.

**Q: Is there any AI/ML?**
A: No. The problem is cryptographic evidence; adding AI would be dishonest.

**Q: Is it a blockchain?**
A: It is a **replicated, independently-signed, Merkle-checkpointed ledger**. Not a
consensus blockchain. Say "DLT-style" carefully.

**Q: How is this different from ordinary watermarks?**
A: The ID is per-session and opaque, and it is cryptographically backed by a signed ledger
with per-node quorum, not a mutable database.

**Q: What exactly does a successful verify prove?**
A: That the artifact carries a watermark derived from a recorded session, the recipient's
ML-DSA signature over that event verifies, and a quorum of node keys signed the same entry.
It does **not** prove a human acted.

**Q: Why ML-DSA-65 and ML-KEM-768?**
A: NIST Level 3; balanced keys/signatures/performance. 512/1024 and 44/87 are available in
the wrapper.

**Q: Why not encrypt the whole file with ML-KEM?**
A: KEMs encapsulate a fixed-size secret. The file is AES-256-GCM; ML-KEM only wraps the AES key.

**Q: What if the recipient is also the sender?**
A: Sender can decrypt if listed as a recipient.

**Q: Can I demo with custom accounts?**
A: Yes. Register a new account (3–24 chars `A-Z0-9_`, passphrase ≥ 8). New accounts have
encrypted keys and require unlock.

## B. Troubleshooting

### Backend / setup

| Symptom | Cause | Fix |
|---|---|---|
| `ModuleNotFoundError: pqcrypto` | deps not synced | `uv sync --python 3.11` |
| `Address already in use` | port 8000 busy | use `--port 8001` and update the Vite proxy |
| App starts but `/` is blank | `frontend/dist` missing | `cd frontend && npm run build` |
| `/api/*` 404 from Vite | proxy target wrong | set `server.proxy['/api']` to `http://localhost:8000` |
| Tests fail on import | running from the wrong cwd | run from repo root; `pythonpath=["."]` is configured |
| Docker build OOM/slow | PQC wheel + npm install | build with more memory or build the frontend first |

### Auth / keys

| Symptom | Cause | Fix |
|---|---|---|
| "Private key is locked" (403) | 30-min unlock expired or new session | Unlock with your passphrase, or log in again |
| Login 401 | unknown user or wrong passphrase | check spelling/case (usernames are uppercased) |
| Registration 400 | username/passphrase invalid | 3–24 `A-Z0-9_`; passphrase ≥ 8 |
| Username "taken" | case-insensitive uniqueness | pick another |
| `ALICE`/`BOB` can't be re-registered | they exist as legacy demo users | use them directly |

### Decryption / downloads

| Symptom | Cause | Fix |
|---|---|---|
| Decrypt 403 "not authorized" | you are not in `authorized_recipients` | use the sender or a listed recipient |
| Document 404 | `DOC-XXX` missing from `storage/encrypted` | re-upload |
| Download 401 | no token and no bearer session | use the `download_url` from the decrypt response |
| Download 403 | token file mismatch | use the token issued for **that** file |
| Download fails after 10 min | token expired | decrypt again |
| Output is `.zip` unexpectedly | the type/handler fell back to container | expected; see the per-format matrix |

### Watermark / verify

| Symptom | Verdict | Meaning |
|---|---|---|
| `NO_WATERMARK` | no CRC-valid ID found | artifact was transformed/stripped, or not watermarked |
| `NO_LEDGER_MATCH` | ID found but absent from ledger | forged/altered ID, or ledger was reset |
| `SIGNATURE_INVALID` | event was modified | tampered record |
| `LEDGER_TAMPERED` | quorum failed | not validly replicated on enough nodes |
| `VERIFIED` | all checks pass | recipient/session attributed |
| Message mentions a divergent node | strict chain check failed but quorum passed | run `/api/ledger/repair` |

### Ledger

| Symptom | Cause | Fix |
|---|---|---|
| Integrity FAILED after a demo | a tamper demo left a node dirty (should auto-restore) | `POST /api/ledger/repair` |
| Need a clean slate | previous experiments | truncate `node*/ledger.jsonl` + `checkpoints.jsonl` (`clear_ledger()`), or delete runtime files |
| LAN commit refuses | fewer than quorum reachable | start the missing nodes; check `/api/ledger/members` |
| Node not joining | wrong coordinator URL / token / firewall | verify `BOUND_COORDINATOR_URL`, `BOUND_ENROLL_TOKEN`, same subnet |
| Node rejoins rejected | public key changed | it was pinned; remove the member first or restore the original key |
| Audit shows a node offline | device asleep/unreachable | expected; it is reported, not dropped |
| `ledger-tampering` demo skipped | you are in LAN mode | it only applies to local mode; tamper on the device instead |

### LAN / Windows

| Symptom | Fix |
|---|---|
| PowerShell script errors on empty args | use the env-var form (`$env:BOUND_NODE_ID=…`) or pass named params |
| Nodes can't see each other | disable client/AP isolation; put all devices on one subnet |
| No internet on the router | that is the point; do not connect a WAN cable |
| `/node/info` exposed a private key? | it does not; only `public_key_b64` is returned |

## C. Reset recipes

```bash
# clean ledger (keeps node keys)
uv run python -c "from backend.app.ledger.ledger import clear_ledger; clear_ledger()"

# full runtime reset (Linux/macOS)
rm -rf storage/encrypted/* storage/watermarked/* backend/data/* \
       ledger/node*/ledger.jsonl ledger/node*/checkpoints.jsonl ledger-members.json

# remove LAN node state for a device
rm -rf ledger-lan/<node_id>
```

> Never delete `backend/keys/*` or `ledger/node*/node_mldsa_*.b64` — removing key files
> invalidates existing ledger signatures and watermarks.
