## 1. End-to-end flow (the PS's 20 steps, as built)

```text
 1. Sender uploads a document                          POST /api/encrypt
 2. SHA-256 hash of the plaintext                      encryption/document.py
 3. Random AES-256 key generated                        encryption/aes.py
 4. AES-256-GCM encrypts the file                       encryption/aes.py:7
 5. Per-recipient ML-KEM-768 encapsulation of the key   encryption/document.py:67
 6. Encryption metadata stored as DOC-XXX.json          storage/encrypted/
 7. Recipient authenticates + unlocks keys              POST /api/auth/login|unlock
 8. Recipient requests decryption                       POST /api/decrypt
 9. ML-KEM decapsulation → AES key → plaintext          encryption/document.py:134
10. Fresh session + nonce generated                     forensic/events.py:75
11. Watermark ID derived (128-bit)                      dct_watermark.py:44
12. Format dispatcher embeds watermark                  watermark/formats.py:71
13. Watermarked bytes saved (original format)           services/decryption_service.py:94
14. Canonical event created                             forensic/events.py:25
15. Recipient ML-DSA-signs the event                    forensic/events.py:40
16. Event committed to ledger with quorum               ledger/ledger.py:534
17. Each node signs entry + Merkle checkpoint           ledger/ledger.py:224,272
18. Download URL issued (HMAC token, 10 min)            main.py:97
19. Leaked artifact uploaded to verifier                POST /api/verify
20. Extract → find → verify sig → verify quorum → done  forensic/verify.py:22
```

## 2. Encryption step (sender)

`encrypt_document()` at `backend/app/encryption/document.py:34`:

1. Validates every recipient exists in the registry.
2. `doc_hash = SHA-256(plaintext)`.
3. `doc_id = DOC-<next int>`.
4. `aes_key = 32 random bytes`.
5. `nonce, ciphertext = AES-256-GCM(aes_key, plaintext)`.
6. For each recipient: `kem_ct, ss = ML-KEM-768.Encap(recipient_pk)`, then
   `wrap_nonce, wrapped = AES-256-GCM(ss, aes_key)`.
7. Writes one JSON file `storage/encrypted/DOC-XXX.json`.

> Note: the ciphertext is one; there is **one wrapped AES key per recipient**.
> Full ciphertext is stored regardless of document size (prototype-grade file storage).

## 3. Decryption + watermark step (recipient)

`recipient_decrypt_and_watermark()` at `services/decryption_service.py:65`:

1. `get_private_keys(rid)` — requires an active unlock or a passphrase. Raises `PermissionError` if locked.
2. `decrypt_document()` — ML-KEM decap → unwrap AES key → AES-GCM decrypt →
   re-verifies `SHA-256(plaintext) == document_hash` (tamper check).
3. `session_id, nonce = generate_session_and_nonce()`.
4. `watermark_id = generate_watermark_id(document_hash, rid, session_id, nonce)`.
5. `formats.embed_watermark(bytes, wm, filename)` — the dispatcher.
6. If a handler silently fell back to a container, the suffix is corrected to `.zip`.
7. Output filename: `DOC-XXX_ALICE_SES-XXXXXX_<safestem><ext>` under `storage/watermarked/`.
8. Event created and signed with the recipient's ML-DSA-65 key.
9. `commit_event()` writes to the ledger with quorum; `verify_entry_quorum()` confirms.
10. API returns watermark/session/nonce/hashes/signature (truncated + full) + quorum + download URL.

## 4. Format dispatch step

`formats.embed_watermark()` at `watermark/formats.py:71`:

```text
extension → pdf | image | text | ooxml
no extension / unknown → sniff bytes → pdf(%PDF) | ooxml | image | text | container
handler raises ContainerFallback or any exception → ZIP container fallback
```

`extract_watermark()` is defensive: it tries the native channel, then container for ZIPs,
then PDF magic, then a UTF-8 zero-width scan, then returns `None`. It never raises.

- ✅ **VALIDATED:** `test_extract_never_raises_on_garbage`.

## 5. Ledger commit step (local mode)

`commit_event()` at `ledger/ledger.py:534`:

1. Canonical-serialize the event (`json.dumps(sort_keys=True, separators=(',',':'))`).
2. `previous_hash` = **majority** of the 4 nodes' last hashes.
3. `current_hash = SHA256(canon_event ‖ recipient_signature ‖ previous_hash)`.
4. For each node that can participate (chain valid, seq continuous, head == previous_hash):
   - build entry with that node's `node_id` and `node_signature`,
   - build a signed Merkle checkpoint over all entry hashes,
   - append entry + checkpoint (with `fsync`).
5. Require **≥ 3 successes**, else raise `RuntimeError` (quorum not reached).
6. Return a representative entry.

- ✅ **VALIDATED:** `test_ledger_v2.py::test_commit_refuses_without_quorum_after_multi_node_tamper`.

## 6. LAN commit step

`lan.commit_event()` at `ledger/lan.py:114`:

1. Collect `/node/info` from all members; require at least `quorum` reachable.
2. `(seq, previous_hash)` = **majority head** among reachable nodes.
3. Recompute `current_hash` locally.
4. `POST /node/append` to every member; each node independently re-derives and validates
   `current_hash` before signing.
5. Require at least `quorum` successes.

- ✅ **VALIDATED:** `test_ledger_lan.py` (4 real processes on localhost).

## 7. Forensic verification step

`forensic_verify()` at `forensic/verify.py:22`:

1. `format = formats.handler_kind(filename, bytes)`.
2. `watermark_id = formats.extract_watermark(bytes, filename)`.
   - none → `NO_WATERMARK`.
3. `entry = find_by_watermark(watermark_id)`.
   - none → `NO_LEDGER_MATCH` ("may be forged or altered").
4. Extract recipient/session/document/timestamp.
5. `verify_event_with_provided_pk(event, signature, public_key_b64, variant)`.
6. `verify_all_ledgers()` — strict: all nodes valid + identical chain.
7. `verify_entry_quorum(watermark_id)` — ≥ 3 nodes (local) or majority (LAN) share the same
   `current_hash` and each chain prefix is valid.
8. Status:
   - signature invalid → `SIGNATURE_INVALID`
   - quorum failed → `LEDGER_TAMPERED`
   - else → `VERIFIED` (message notes if the strict full-chain check found a divergent node).

## 8. Session lifecycle

| Action | Endpoint | Lifetime |
|---|---|---|
| Login | `POST /api/auth/login` | session token 12 h; also unlocks keys |
| Unlock keys | `POST /api/auth/unlock` | in-memory keys 30 min |
| Lock keys | `POST /api/auth/lock` | drops cached keys immediately |
| Logout | `POST /api/auth/logout` | invalidates token |
| Download mark | `GET /api/watermarked/{file}?token=` | HMAC token 10 min, or a valid bearer session |

Sessions persist to `backend/data/sessions.json` (survives restart); unlocks are memory-only.

## 9. Failure paths that are handled

| Failure | Behaviour |
|---|---|
| Locked keys | HTTP 403, unlock prompt |
| Wrong passphrase | 401 login / 403 unlock; private-key decrypt raises `PermissionError` |
| Not authorized for doc | 403 on decrypt and on document events |
| Unknown recipient at encrypt | 400 (`Recipient X not registered`) |
| Empty file / no extension | 400 |
| Quorum not reachable | commit raises; LAN returns an explicit error |
| One node corrupted | attribution still succeeds via quorum; repair endpoint re-syncs |
| Unsupported/unsafe format | transparent ZIP container fallback, extension corrected |
