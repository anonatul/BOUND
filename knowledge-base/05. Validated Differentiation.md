## 2. What IS the differentiation

### 2.1 Session-scoped fingerprints (not just recipient-scoped)
Watermark =
`SHA-256(document_hash | recipient_id | session_id | nonce)[:16]` → `WM-` + 26 base32.

- Same recipient decrypting twice gets **two different IDs**.
- The nonce is 128 bits of OS randomness; session ID is fresh per decryption.
- ✅ **VALIDATED:** `test_crypto.py::test_watermark_generation_uniqueness`,
  `test_watermark_v2.py::test_watermark_id_uniqueness_across_recipients_and_sessions`.

### 2.2 The fingerprint is opaque and ledger-bound
The artifact contains no identity, only a 128-bit opaque ID. The recipient mapping lives
only in the ledger.

- ✅ **VALIDATED:** `generate_watermark_id()` hashes inputs; extraction returns the ID only.

### 2.3 Real per-node PQC signatures (not one server key)
Each ledger node has its own ML-DSA-65 keypair and signs:
- every entry it stores (`node_signature` over 9 canonical fields), and
- every Merkle checkpoint.

Node signatures differ per node for the same event. Rewriting all four files consistently
still fails because node private keys cannot be forged.

- ✅ **VALIDATED:** `test_ledger_v2.py::test_commit_two_events_all_nodes_valid_with_independent_node_signatures`
  asserts `len(set(node_signatures.values())) == len(NODE_IDS)`.
- ✅ **VALIDATED:** `test_ledger_v2.py::test_admin_without_node_keys_cannot_rewrite_all_nodes`.

### 2.4 Offline quorum with survival
A **3-of-4** quorum for local mode and a **strict majority of joined devices** for LAN mode.
Attribution survives one corrupt node.

- ✅ **VALIDATED:** `test_ledger_v2.py::test_one_corrupt_node_attribution_survives_quorum`.
- ✅ **VALIDATED:** `test_ledger_lan.py` runs 4 real node-agent processes and proves
  commit, quorum, divergence and peer repair.

### 2.5 No-single-admin guarantee, structurally
In LAN mode each node's ML-DSA key is generated on and never leaves its device. The
coordinator cannot produce valid node signatures. This is the structural version of the
"no single administrator" requirement.

- ✅ **VALIDATED (design + LAN tests):** keys chmod `0600`, only the public key is ever
  returned by `/node/info`; the append request is independently re-derived and validated
  by the node before it signs.

### 2.6 Format-native output that does not destroy the document
- PDF `preserve` mode: the original PDF is edited in place. Vector text remains selectable
  and searchable; only embedded raster images are re-encoded.
- Measured on the included sample: source **2,969 B** → watermarked **2,632 B** (it can get
  smaller because image streams are re-encoded).
- ✅ **VALIDATED:** `test_watermark_v2.py::test_preserve_mode_keeps_text_selectable`,
  `test_preserve_size_below_1_5x`, `test_preserve_mode_watermarks_embedded_image`.

### 2.7 Any-file-type coverage with an honest fallback
PDF / image / text / OOXML are native; **everything else** uses a ZIP container comment. The
fallback is documented as protecting the wrapper only.

- ✅ **VALIDATED:** `test_watermark_formats.py` covers all handlers + fallback + safety.

### 2.8 Fully offline, zero cloud, zero public chain
No network calls at runtime beyond the isolated LAN in LAN mode.

- ✅ **VALIDATED:** code uses only local files, `urllib` to LAN members, and stdlib.

## 3. The one-slide differentiation

```text
Digimarc / DRM        → per-copy ID, but a mutable registry and no PQC
Blockchain products   → tamper-evident, but online and not artifact-bound
Access logs           → mutable by the same admin you are investigating
BOUND                 → artifact-bound 128-bit session fingerprint
                        + recipient ML-DSA signature
                        + offline per-node-signed quorum ledger
                        + fully offline
```

> **BOUND = (per-session invisible fingerprint) × (post-quantum signatures) × (offline
> independently-signed quorum ledger), in one chain of evidence.**

## 4. Claims checklist for the pitch

| Claim you want to make | Allowed? | Exact wording |
|---|---|---|
| "Different fingerprint per session" | ✅ | "Every decryption derives a new 128-bit fingerprint from a fresh session and nonce." |
| "Tamper-evident ledger" | ✅ | "Any edit breaks per-node signatures and Merkle checkpoints." |
| "No single admin can rewrite history" | ✅ LAN | "In LAN mode each node key lives on a separate device." |
| "Quantum-safe" | ✅ scoped | "Key establishment and signatures are NIST PQC." |
| "Blockchain" | 🟡 careful | "A permissioned, independently-signed DLT-style ledger; not a consensus blockchain." |
| "AI-powered" | 🔴 | Do not say it. |
| "Watermark cannot be removed" | 🔴 | Do not say it. |
| "Survives screenshots/photos" | 🔴 | Do not claim; offer rasterize mode as the research direction. |
