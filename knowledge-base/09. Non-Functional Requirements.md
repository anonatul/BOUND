> **Status:** Living document

## 1. Offline / air-gapped

| ID | Requirement | How | Status |
|---|---|---|---|
| NFR-1 | No internet, cloud, KMS, or public chain | local files + isolated LAN `urllib` only | ✅ |
| NFR-2 | No DNS needed on the LAN | static IPs; node URL from observed source IP | ✅ |
| NFR-3 | Works on one laptop with no network | `BOUND_LEDGER_MODE=local` | ✅ |
| NFR-4 | Optional enrollment gate for LAN joining | `BOUND_ENROLL_TOKEN` | ✅ |

## 5. Security properties

| ID | Requirement | Mechanism | Status |
|---|---|---|---|
| NFR-22 | Ciphertext authenticated | AES-GCM tag | ✅ |
| NFR-23 | Private keys encrypted at rest | scrypt (n=2¹⁴,r=8,p=1) + AES-256-GCM | ✅ |
| NFR-24 | Session tokens unguessable | `secrets.token_urlsafe(32)` | ✅ |
| NFR-25 | Downloads time-limited | HMAC-SHA256 token, 10 min | ✅ |
| NFR-26 | Node private keys never leave device | LAN mode, chmod 0600 | ✅ |
| NFR-27 | Watermark ID opaque | hash-derived, 128-bit | ✅ |
| NFR-28 | Constant-time token compare | `hmac.compare_digest` | ✅ |

## 9. Explicit non-goals

- No horizontal scale / clustering.
- No rate limiting.
- No fuzzing / formal verification.
- No TLS by default in LAN mode (recommended future: local self-signed CA).
- No backup/replication beyond the ledger quorum.
- No multi-tenant isolation.
