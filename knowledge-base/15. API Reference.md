# 15. API Reference

> **Status:** Living document
> **Version:** 1.0
> **Last Updated:** 2026-09-27
> **Source of truth:** `backend/app/main.py`, `backend/app/ledger/node_agent.py`
> Interactive docs are served at `/docs` (FastAPI/OpenAPI).

Auth column: `Bearer` = requires `Authorization: Bearer <token>`; `-` = public;
`optional` = works without a token but accepts one.

---

## 1. System

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/api/health` | - | Health + PQC/ledger summary |

## 2. Authentication (`backend/app/auth`)

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/api/auth/register` | - | Create account with encrypted keys |
| GET | `/api/auth/username-available?username=` | - | Case-insensitive availability check |
| POST | `/api/auth/login` | - | Verify passphrase, unlock, issue token |
| POST | `/api/auth/unlock` | Bearer | Re-unlock keys for 30 min |
| POST | `/api/auth/logout` | Bearer | Invalidate session |
| GET | `/api/auth/me` | Bearer | Current user + unlock state |
| POST | `/api/auth/lock` | Bearer | Drop in-memory private keys |

Request bodies:
```json
// register
{"username": "CAROL", "display_name": "Carol", "passphrase": "at-least-8"}
// login / unlock
{"username": "CAROL", "passphrase": "…"}   // unlock: {"passphrase": "…"}
```

## 3. Recipients

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/api/recipients` | - | Public registry + key fingerprints + doc counts |
| GET | `/api/recipients/{recipient_id}` | - | One public profile |
| POST | `/api/recipients/ensure` | - | Create demo recipients if missing |

`_recipient_payload` fields: `recipient_id, display_name, mldsa_variant, mlkem_variant,
key_storage, created_at, mlkem_fingerprint, mldsa_fingerprint, documents_owned,
documents_shared`. `*_fingerprint` = first 16 hex of SHA-256(public key).

## 4. Documents (sender)

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/api/encrypt` | Bearer | Multipart: `file`, `recipients` (JSON array or CSV) |
| GET | `/api/documents` | Bearer | Docs where you are owner/recipient, with role + counts |
| GET | `/api/documents/{document_id}` | Bearer | Metadata (strips `wrapped_keys`/`ciphertext`) |
| GET | `/api/documents/{document_id}/events` | Bearer | Every recorded decryption session + quorum |

`/api/encrypt` response: `document_id, document_hash, original_filename, original_extension,
content_type, sender_id, authorized_recipients, ciphertext_len, status, message`.

Document events item: `recipient_id, session_id, watermark_id, timestamp, current_hash,
previous_hash, quorum_ok, valid_nodes`.

## 5. Decryption & download (recipient)

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/api/decrypt` | Bearer | Decrypt → watermark → sign → commit |
| GET | `/api/watermarked/{filename}?token=` | token or Bearer | Download one marked copy |
| GET | `/api/watermarked` | - | List marked files |

`POST /api/decrypt` body: `{"document_id": "DOC-001"}` (optional `recipient_id`, must equal you).

Response highlights:
```json
{
  "status": "DECRYPTED",
  "document_id": "DOC-001",
  "recipient_id": "ALICE",
  "session_id": "SES-9F82A1",
  "watermark_id": "WM-…",
  "nonce": "…",
  "document_hash": "…",
  "watermarked_hash": "…",
  "signature": "<first 64 chars>…",
  "signature_full": "…",
  "ledger": {"previous_hash": "…", "current_hash": "…",
             "node_quorum": 4, "valid_nodes": ["node1","node2","node3","node4"],
             "timestamp": "…"},
  "ledger_status": "COMMITTED (4/4 nodes)",
  "download_url": "/api/watermarked/…?token=…",
  "filename": "…", "content_type": "…",
  "output_format": "pdf|image|text|ooxml|container",
  "original_filename": "report.pdf",
  "message": "Decryption successful. Watermark generated and ledger committed."
}
```

Download token: HMAC-SHA256 over base64url `{f, r, e}`, TTL **10 min**. A valid bearer session
is also accepted. A token bound to file A cannot download file B (403).

## 6. Ledger

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/api/ledger` | - | Entries with quorum/integrity/merkle/mode/members |
| GET | `/api/ledger/nodes` | - | Per-node entries + integrity |
| POST | `/api/ledger/verify` | - | Strict verification + details |
| POST | `/api/ledger/repair` | - | Re-sync divergent nodes from the valid quorum |
| GET | `/api/ledger/members` | - | Registered members + required quorum |
| POST | `/api/ledger/register` | - (token) | Node announces itself; optional `BOUND_ENROLL_TOKEN` |
| DELETE | `/api/ledger/members/{node_id}` | - | Remove a member |

`GET /api/ledger` fields: `entries, count, integrity, integrity_valid, quorum, quorum_ok,
merkle_root, divergent_nodes, details, mode, members, note`. Each entry is annotated with
`quorum_ok` and `valid_nodes`.

## 7. Forensic verification

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/api/verify` | optional | Multipart `file` → full forensic verdict |
| POST | `/api/verify/watermark-only` | optional | Extract only (fast) |

Verdict fields: `status (VERIFIED|NO_WATERMARK|NO_LEDGER_MATCH|SIGNATURE_INVALID|
LEDGER_TAMPERED), format, watermark_id, watermark_detected, ledger_match_found,
signature_valid, ledger_valid, ledger_quorum_ok, node_quorum, recipient_id, session_id,
document_id, timestamp, event, leaked_hash, message`.

## 8. Security demos

| Method | Path | Auth | Proves |
|---|---|---|---|
| POST | `/api/test/different-recipients` | optional | ALICE ≠ BOB watermark |
| POST | `/api/test/attribution` | optional | Latest ALICE file → VERIFIED |
| POST | `/api/test/signature-tampering` | optional | Modified event → signature INVALID |
| POST | `/api/test/ledger-tampering` | optional | Single-node edit → integrity FAILED |
| POST | `/api/test/ledger-admin-tampering` | optional | All-node consistent rewrite → rejected |
| POST | `/api/test/fake-watermark` | optional | Unknown WM → NO_LEDGER_MATCH |
| POST | `/api/test/end-to-end` | optional | Full encrypt→decrypt→leak→verify |

`ledger-tampering` and `ledger-admin-tampering` return `{"skipped": true}` in LAN mode,
because those demos edit local files and the real attack lives on separate devices.

## 9. Ledger node agent API (`node_agent.py`, LAN mode)

| Method | Path | Description |
|---|---|---|
| GET | `/health` | liveness |
| GET | `/node/info` | node_id, public key, count, last hash |
| GET | `/node/entries` | full chain |
| GET | `/node/find?watermark_id=` | entry + chain-prefix validity |
| POST | `/node/append` | coordinator proposal; node validates then signs |
| POST | `/node/verify` | node self-verify |
| POST | `/node/sync` | adopt a peer chain with local re-signing |

Node error semantics:
- `409` on `seq` or `previous_hash` mismatch.
- `400` when `current_hash` does not match `SHA256(event+signature+previous_hash)`.
- `/node/sync` refuses an empty chain.

## 10. Frontend service layer

`frontend/src/services/api.js` wraps all of the above. `setUnauthorizedHandler` lets the app
drop to the login screen on any 401. `fileTypes.js` maps `pdf|image|text|ooxml|container` to
display labels.
