## 2. Backend module map

| Module | Responsibility |
|---|---|
| `backend/app/main.py` | FastAPI app, all HTTP routes, download tokens, demos, static frontend |
| `backend/app/crypto/pqcrypto_wrapper.py` | ML-KEM / ML-DSA keygen, encaps, decaps, sign, verify, b64 helpers |
| `backend/app/encryption/aes.py` | AES-256-GCM encrypt/decrypt, key wrap/unwrap under KEM secret |
| `backend/app/encryption/document.py` | Encrypt-once-per-recipient model, decrypt, hash check |
| `backend/app/identity/manager.py` | Accounts, encrypted private keys, unlock store, registry |
| `backend/app/auth/service.py` | Sessions (persisted), login/logout, TTL pruning |
| `backend/app/auth/deps.py` | FastAPI bearer dependencies |
| `backend/app/forensic/events.py` | Canonical event, session/nonce, sign, verify |
| `backend/app/forensic/verify.py` | Forensic pipeline and final verdict |
| `backend/app/services/decryption_service.py` | Recipient decrypt → watermark → sign → commit orchestration |
| `backend/app/watermark/dct_watermark.py` | Watermark ID, PDF channels (invisible text + DCT QIM), rasterize |
| `backend/app/watermark/formats.py` | Dispatcher: extension + magic sniff → handler, fallback |
| `backend/app/watermark/handlers/common.py` | Shared payload framing, zero-width marker, extension sets |
| `backend/app/watermark/handlers/image.py` | Y-channel DCT QIM image handler |
| `backend/app/watermark/handlers/text.py` | Zero-width text handler |
| `backend/app/watermark/handlers/ooxml.py` | OOXML zero-width handler |
| `backend/app/watermark/handlers/container.py` | ZIP comment generic fallback |
| `backend/app/ledger/ledger.py` | Per-node keys, entries, checkpoints, quorum, repair (local) |
| `backend/app/ledger/members.py` | Dynamic membership + majority quorum rule |
| `backend/app/ledger/lan.py` | Coordinator client to remote node agents |
| `backend/app/ledger/node_agent.py` | Standalone per-device ledger node service |

## 3. Layered view

```text
Presentation   React SPA (pages + components)  /  FastAPI-served static build
API            FastAPI routes (auth, files, verify, ledger, demos)
Orchestration  decryption_service, forensic.verify
Domain         identity, encryption, watermark, ledger, forensic
Primitives     pqcrypto (ML-KEM/ML-DSA), cryptography (AES-GCM/scrypt/HMAC)
Persistence    local files (JSON/JSONL), storage dirs, keys dir
Transport      in-process (local) | HTTP to node agents (LAN)
```

## 4. Trust boundaries

1. **Browser ⇄ coordinator** — bearer session; CORS `*` in the prototype.
2. **Coordinator ⇄ witness nodes (LAN)** — plain HTTP; the isolated router is the boundary.
3. **Coordinator filesystem ⇄ node keys** — in local mode the node keys sit with the files
   (prototype weakness); in LAN mode keys are on separate devices.
4. **Recipient endpoint** — not protected (no DRM/TEE); stated honestly.

## 5. Request path for the critical flow

```text
User clicks Decrypt (SharedWithMe)
   → POST /api/decrypt (Bearer)
   → load_encrypted_document + authorization check
   → is_unlocked(rid) check
   → recipient_decrypt_and_watermark()
        → decrypt_document (ML-KEM + AES-GCM + hash check)
        → generate_session_and_nonce
        → generate_watermark_id
        → formats.embed_watermark
        → create_decryption_event
        → sign_event (ML-DSA)
        → commit_event + verify_entry_quorum
   → make_download_token (HMAC, 10 min)
   → 200 {watermark_id, session_id, signature, ledger, download_url, …}
User clicks Download
   → GET /api/watermarked/<file>?token=…
   → verify_download_token OR bearer session
   → FileResponse (native extension or .zip)
```

## 6. Why this architecture

| Choice | Reason |
|---|---|
| FastAPI | async uploads, automatic OpenAPI docs at `/docs`, simple demo endpoints |
| Files not DB | fully self-contained, portable, offline, no DB engine to install |
| Per-node keys | structural, not policy, no-single-admin property |
| Dispatcher + fallback | any file type is supported without lying about native coverage |
| Plain HTTP on LAN | air-gapped router is the boundary; removes TLS setup friction in a demo |
| React + Vite | fast dev loop; built assets served by FastAPI for one-command demo |

## 7. Container topology

`docker-compose.yml` runs a single `app` service with volumes for `ledger/`, `storage/`,
`backend/keys/`. The 4 ledger nodes are **directories written by one process** in local
mode — the compose file is honest that "in a production system these would be separate
processes". LAN mode is the real multi-device topology, run outside Docker per device.
