## 2. v1 → v2 changes (from the README table)

| Area | v1 | v2/v2.1 |
|---|---|---|
| Output size | 124 KB → 44–115 MB (PNG raster) | 3 KB PDF → ~2.6 KB |
| Fidelity | image-only, no selectable text | original PDF preserved, text selectable |
| Watermark entropy | 48-bit (`WM-` + 12 hex) | 128-bit (`WM-` + 26 base32) |
| Channels | DCT only | invisible PDF text + DCT QIM + zero-width + container |
| Formats | PDF only | PDF, image, text, OOXML, container |
| Identity | hardcoded ALICE/BOB, plaintext keys | accounts, encrypted keys, sessions, unlock |
| Ledger | 4 JSONL files, nominal quorum | per-node ML-DSA signing, checkpoints, real quorum |
| Admin tamper | pass | rejected via node signatures |
| Attribution resilience | single node tamper broke it | survives one corrupt node |
| Frontend | crypto dashboard | file-sharing app with Verify + Audit |

## 3. Key design decisions (with rationale)

| # | Decision | Rationale | Alternative rejected |
|---|---|---|---|
| D1 | Custom signed ledger over Fabric | offline, zero infra, structural no-single-admin | Hyperledger Fabric |
| D2 | Per-node ML-DSA keys | signatures cannot be forged from files alone | one server signing key |
| D3 | Session+nonce watermark derivation | distinguishes sessions, not just recipients | per-recipient only |
| D4 | DCT QIM coefficient (3,2), Q=16 | balance invisibility/robustness; survives JPEG | DWT, SVD |
| D5 | Invisible PDF text channel | exact recovery, preserves selectable text | rasterize-everything |
| D6 | `preserve` default, `rasterize` optional | fidelity first, robustness opt-in | rasterize default |
| D7 | Zero-width Unicode for text/OOXML | no visible change, format-safe insertion | whitespace tricks |
| D8 | ZIP comment fallback for any type | support everything without lying | reject unsupported types |
| D9 | scrypt + AES-GCM encrypted keys | protect private keys at rest | plaintext keys |
| D10 | LAN majority-of-members quorum | offline nodes cannot lower the bar | fixed 3/4 |
| D11 | URL from observed source IP on join | a node cannot claim another's address | self-declared URL |
| D12 | Repair by local re-signing | no trust in file copies | copy from trusted node |
| D13 | No AI/ML | the problem is cryptographic evidence | add NLP buzzwords |
| D14 | Honest limitation sections | PS demands it; judges reward it | hide weaknesses |

## 4. What is "done" vs "future"

**Done (validated):**
- Real PQC, AES-GCM, sessions, encrypted keys.
- Per-session watermarks across 5 format classes.
- Per-node signed ledger, checkpoints, quorum, repair.
- LAN multi-device mode with dynamic membership.
- Forensic verifier + web app + 110 tests.

**Future (not built):**
- Client-side / hardware signing (true non-repudiation).
- Hardened viewer / TEE.
- Camera and print-scan robustness experiments.
- Independent security audit.
- TLS with local CA; rate limiting; database/scale.

## 5. Lessons logged

1. Fidelity matters: rasterizing every page was the v1 mistake; preserve mode fixed it.
2. Entropy matters: 48-bit IDs were too weak; 128-bit now.
3. "Quorum" must be real: per-node keys made the tamper demo actually fail.
4. The strongest requirement (no single admin) is a **topology** property, not a code flag —
   hence LAN mode.
5. Honesty is a feature under SIH judging.
