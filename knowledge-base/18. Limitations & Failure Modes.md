# 18. Limitations & Failure Modes

> **Status:** Living document
> **Version:** 1.0
> **Last Updated:** 2026-09-27
> **Rule:** every item here must be stated before a judge finds it. Hiding these loses credibility.**

## 1. Cryptographic / identity limitations

| # | Limitation | Impact | Fix path | Label |
|---|---|---|---|---|
| L1 | Private keys held by the server after unlock; server signs for the recipient | weakens non-repudiation | client-side signing (WASM/liboqs) or hardware key/HSM | 🔴 current |
| L2 | `ALICE`/`BOB` demo keys are plaintext on disk | demo-only; not secure | remove/convert | 🔴 current |
| L3 | No key rotation / revocation | a compromised key stays valid | add key lifecycle | 🔵 future |
| L4 | No forward secrecy | long-term key compromise exposes past wrapped keys | hybrid + ratcheting | 🔵 future |
| L5 | No HSM/TPM/Secure Enclave | keys live in process memory | hardware-backed keys | 🔵 future |

## 2. Watermark limitations

| # | Limitation | Impact | Label |
|---|---|---|---|
| L6 | Screenshot / camera capture loses the watermark | attribution fails | 🔴 |
| L7 | Print + scan loses it | attribution fails | 🔴 |
| L8 | Re-typing / content recreation removes it | attribution fails | 🔴 |
| L9 | Flattening a `preserve` PDF to a bare image loses the text channel (DCT remains only if images existed) | weaker/absent attribution | 🟡 |
| L10 | Text zero-width markers can be stripped by editors/pipelines | attribution fails | 🟡 |
| L11 | OOXML markers survive normal editing but not deliberate removal | attribution fails | 🟡 |
| L12 | Image DCT degrades under aggressive rescale / repeated recompression | attribution may fail | 🟡 |
| L13 | ZIP container watermark protects only the wrapper; extracted inner file loses it | attribution fails | 🟡 |
| L14 | Tiny / palette / animated images and unsafe types fall back to container | covered by fallback, with L13 caveat | ✅ documented |
| L15 | Watermark is "robust against selected transforms", NOT unremovable | must be stated | 🔴 never overclaim |

## 3. Ledger / DLT limitations

| # | Limitation | Impact | Label |
|---|---|---|---|
| L16 | Not a BFT consensus network; no formal fault model proof | not production-grade | 🔴 |
| L17 | Local mode node keys are colocated with ledger files | privileged file+key attacker can forge | 🔴 local; ✅ mitigated in LAN |
| L18 | No protection if a majority of node keys are compromised | history can be forged | 🔴 |
| L19 | O(n) Merkle recompute per append | slow at scale | 🟡 |
| L20 | JSONL append not cross-process locked | concurrent writers could interleave | 🟡 |
| L21 | No TLS on the LAN by default | sniffing on the LAN possible; LAN is assumed isolated | 🟡 |
| L22 | Repair trusts a majority chain to define "canonical" | a majority can impose a chain | 🟡 by design |

## 4. Application / operational limitations

| # | Limitation | Impact | Label |
|---|---|---|---|
| L23 | No rate limiting / lockout | brute-force passphrase attempts possible | 🟡 |
| L24 | CORS `*`, localStorage token | XSS-theft risk in a browser context | 🟡 |
| L25 | File storage, no DB | not concurrent-safe; no scale | 🟡 |
| L26 | Watermarked files retained indefinitely | disk growth; marked copies persist | 🟡 |
| L27 | No retention/backup/DR policy | prototype | 🟡 |
| L28 | `BOUND_LEDGER_MODE=local` is the default | the strongest config (LAN) is opt-in | 🟣 |
| L29 | Download tokens can be replayed within 10 min | short window | 🟡 |
| L30 | No fuzzing / formal audit / pen test | unknown bugs | 🟡 |

## 5. Failure modes and behaviour

| Failure | What happens | Available mitigation |
|---|---|---|
| Recipient key locked | decrypt returns 403 | unlock with passphrase |
| Wrong passphrase | 401 login / 403 unlock / `PermissionError` | retry |
| One ledger node corrupted | strict verify fails; attribution still succeeds; node flagged | `/api/ledger/repair` |
| Fewer than quorum nodes reachable (LAN) | commit refuses with an explicit error | bring nodes online |
| Watermarked format unsupported/unsafe | transparent container fallback; suffix `.zip` | documented |
| Malformed ledger JSONL | reported as an error (not silently skipped) | repair from quorum |
| Backend unreachable | frontend shows "check that the backend is running" | start backend |
| Frontend dist missing | API still runs; `/` has no SPA | run `npm run build` |

## 6. The one-line honest boundary

> **BOUND guarantees attribution when (a) the ledger is reachable, (b) a quorum of node keys
> is honest, and (c) the leaked artifact still carries a recoverable watermark. Outside those
> conditions it does not promise attribution, and it says so.**
